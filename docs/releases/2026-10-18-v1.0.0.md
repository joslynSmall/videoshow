## 新增

- 目录搜索没有结果时，弹出视频网站搜索。爱奇艺、腾讯视频、优酷、芒果 TV、哔哩哔哩分栏显示，只出现有结果的网站。
- 点开一条结果后，按该站的播放页地址走原来的解析，并在播放器下方显示分集。直接粘贴播放页地址时，也会补充分集。
- 新增 `GET /api/site-search?kw=` 和 `GET /api/episodes?url=`。
- 站点能力分成三层：契约（站名、域名、`search`、`loadEpisodes`）、编排（并行搜索、按域名归栏、单站失败不影响其他站）、各站实现。之后增加网站，只需登记身份并实现这两个方法。

## 播放修复

优酷页面在 jd 上曾经解析成功但不能播，或直接提示所有线路都解析失败。本地可以播，是因为本机 Chrome 从播放器页面取出了 `sviptq.com` 的播放列表，浏览器可以直接读取。

jd 上做了这些运行环境变更，没有改业务代码：

- 安装 Google Chrome 155。
- `ENABLE_BROWSER_PROVIDER=true`。
- 服务启动改为 `node --experimental-websocket`。jd 的 Node 是 20.19.6，没有全局 `WebSocket`，无头 Chrome 的调试连接因此失败。

修复后，`https://v.youku.com/v_show/id_XNjU2MTM0MDgyMA==.html` 由 `jx-browser` 解析，播放列表允许跨域读取。在 https://videoshow.jiongka.online 上打开后状态为「解析成功」，播放已推进，时长约 13 分钟。

## 限制

- 浏览器解析只在装有 Chrome 的 jd 上可用。Vercel 仍只有 789 接口这一条线路。
- 789 接口对优酷不稳定。它有时返回优酷自己的地址，浏览器不能直接读取；有时直接返回 404。
- 芒果 TV 自己的搜索接口仍会拒绝访问。搜索页抓取依赖 Chrome，可能比接口搜索更慢。
- jd 磁盘在发布前已满。清理系统 journal 和已轮转日志后，剩余约 3.1 GB。Chrome 安装约占其中一部分。
