## 本次变更

### 解析与线路

- 新增 HTTP 渠道适配层：LX、麒麟、789、789 页面入口、冰豆；单次签名链接不预读，避免服务端校验/测速耗尽签名。
- 789 过期时间同时兼容“时长秒数”和“绝对时间戳”；冰豆 MP4 优先读取 `x-expires`，不再固定 45 秒。
- 新增无头浏览器渠道：`jx-browser` 按媒体后缀识别 `m3u8` / `mp4`，修复 B 站 MP4 被误当成 HLS 播放清单读取的问题。
- 新增 `src/media-network.js`：公网 DNS 解析、地址固定和系统 fake-IP 回退；继续执行媒体地址安全校验。
- `/api/race` 返回 `filtered { total, excluded, expired, remaining }`，无候选时前端重新解析一次刷新单次签名地址。
- 冰豆回退条件改为“没有已验证可用线路”，不再因为存在单次链接就跳过。
- DEV 日志新增渠道延迟排行、候选明细、失败 `detail`、换线过滤统计和自动下一集事件。

### 播放器

- 选集栏“全集”旁新增“自动下一集”开关，默认开启；播放结束自动解析下一集，偏好保存到 `localStorage`。
- 全集弹层长标题自动换行，修复文字溢出和横向滚动条。
- 播放倍速扩展为 `0.5、0.8、1.0、1.1–1.9、2.0、2.5、3.0`，其中 1.0–2.0 按 0.1 递增。
- 弹幕默认字号调整为 `20px`。

## 验证

- 本地 `npm test`：119 项，117 通过，0 失败，2 跳过。
- 本地真实解析：B 站 `https://www.bilibili.com/bangumi/play/ep810153` 返回 200，`jx-browser` 以 MP4 通过校验和测速（TTFB 255ms、1351 KB/s）。
- 本地端到端：第 1 集 `ep810152` 播放结束后自动切到第 2 集 `ep810153`，状态为“解析成功”。
- 生产 `/api/health`、页面资源和真实解析结果在部署后补充。

## 部署

- jd：`rsync` 到 `/opt/videoshow`（保留服务器 `.env.local`），运行离线测试，然后 `systemctl restart videoshow`。
- Vercel：从当前代码执行 `vercel --prod`，或推送 `main` 触发 Git 集成部署。
- 回滚：保留上一版 `/opt/videoshow` 目录或发布提交，恢复代码后重启 `videoshow.service`；Vercel 回退到上一部署。

## 限制

- Vercel 没有 Chrome，只能用 HTTP 渠道；需要浏览器取流的线路在 Vercel 不可用。
- `jx-browser` 在 Clash/fake-IP 环境仍可能被媒体安全校验拒绝，需要可用的公网 DNS。
- 789 和冰豆是第三方上游，单集覆盖和稳定性不受本项目控制；B 站仍建议后续增加专用适配器。
- jd 根分区剩余约 3.1 GB，发布前保持监控。
