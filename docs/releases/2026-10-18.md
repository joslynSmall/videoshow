## 本次修复

### 1. 换线时无备用线路（三个叠加缺陷）

现象：主线路 `fragLoadTimeOut` 后换线，日志显示 `expired=2 remaining=0`，最终 `no-alternative` 播放失败。

- **单次签名链接寿命过短**（`src/providers/http.js`）
  原兜底只有 45 秒，而主线路要 40–50 秒才崩溃，备用必然先死。
  改为提取 `singleUseExpiry()`：无 `x-expires` 时给 300 秒；上游声明过短时向上钳到至少 240 秒。
- **`expiresAtMs` 从未进入缓存**（`src/server.js`）
  它只挂在 `candidate` 上，而缓存存的是 `ranked` 数组（不同对象），
  `/api/race` 的过期过滤读到的永远是 `undefined`。
  现已随 `ranked` 一同缓存并输出到 API 响应。
- **“重新解析”没有真的重新解析**（`src/server.js` / `public/app.js`）
  `handleParse` 命中 `getCached` 就直接返回旧数据，导致“刷新单次签名地址”的兜底完全失效。
  新增 `?force=1` 跳过缓存，前端两处刷新路径改用强制解析。

### 2. 卡顿时弹幕整层消失

弹幕插件渲染循环门控在 `art.playing`，而 Artplayer 的 `playing` 要求 `readyState > 2`。
缓冲一耗尽该值立即变 `false`，插件停止推进，已在屏上的弹幕全部变`hidden`。
现接管 `playing` 的读取：只要用户确实想看（已播放过且未暂停未结束）就仍视为正在播放，
画面定格时弹幕静止保留（`public/app.js` 的 `keepDanmakuVisibleDuringStall`）。

### 3. 卡顿检测改为轮询看门狗

原实现依赖 `video:waiting` 事件，存在两个缺陷：HLS.js 卡在首帧时既不派发 `playing` 也不派发 `waiting`（漏判）；真实卡顿时 `waiting` 高频重复派发会不断重置计时器（阈值永远计不满）。
现改为 1 秒轮询 `currentTime` 是否推进，完全不注册 `waiting` 监听。

换线门槛（全部满足）：已播放过或已请求播放、未暂停/未 seek/未结束、`readyState < 3`、连续 8 秒前进不足 1 秒。

### 4. 播放器快进/快退按钮

控制区新增 `⏪` `⏩` 两个可点按钮，每次 ±10 秒（手机无物理键盘，默认方向键不可用）。
目标时间夹在 `[0, duration]`；换线进行中忽略点击。

### 5. 渠道类型日志

服务端在 resolver 定义处标注 `kind`（`api` / `http-api` / `browser`）并透传到 diagnostics 与 candidates，前端不做硬编码推断。
延迟排行新增**剩余寿命**（`剩余=268s` / `已过期`），避免“排行看着还有几条，换线时实际已全过期”。

### 6. jx-browser 退避重试与临时目录泄漏修复

- **退避重试**（`src/providers/jx-browser.js`）
  `jx-browser` 访问解析站 `jx.1ljx.com` 的边缘节点时，会在 TLS 握手前被重置（`ECONNRESET`），表现为页面加载/提取失败。
  改为失败后重试一次（间隔 800ms）；只重试 `PARSE_FAILED`，
  `BROWSER_UNAVAILABLE`（Chrome 未安装）与 `BROWSER_ERROR`（DevTools 端口起不来）属本地环境问题，不重试。
- **临时目录泄漏**
  每次解析都会在 `/tmp/vs-chrome-*` 建profile 目录。原实现在 Chrome 被 SIGKILL 后立即删除，
  因 SingletonLock 等文件仍被占用而失败，目录持续累积（实测已积累 99 个 / 140MB）。
  改为先 SIGTERM、异步退避重试删除、必要时再 SIGKILL；删除不再阻塞事件循环。

## 已知限制

- `singleUse` 候选不参与测速、score 恒为 0：探测单次签名链接会消耗它。代价是单次线路自身卡顿时无法再选第二条单次线路。
- `jx-browser` 拿到的 `sviptq.com` CDN 节点质量有波动，偶发 `benchmark-rejected`（已拿到地址但测速不通过）；同一份代码下会自行恢复，属上游现象。
